# Уведомления Tronaccs: уровень рейтинга от 2

Бот следит за новыми объявлениями Telegram на https://tronaccs.market.
Проверяется именно **уровень рейтинга аккаунта** (`telegram.raiting_level >= 2`),
а не количество Stars, значение рейтинга или репутация продавца.

В уведомлении: уровень, название, цена продавца в рублях, страна, Premium
и кнопка перехода к объявлению. Комиссия сайта в цену продавца не включена:
окончательную сумму показывает сайт.

## Быстрый запуск

1. Создайте бота у https://t.me/BotFather командой `/newbot`.
2. Откройте `config.json`, замените `PASTE_BOT_TOKEN_HERE` своим токеном.
   Токен храните у себя. Не выкладывайте заполненный файл на GitHub.
3. Запустите **Python 3.10 или новее**:

   ```bash
   python main.py
   ```

4. Откройте созданного бота в Telegram и отправьте `/start`.
   Пока вы не нажали «Запустить», бот не сможет написать вам.

Устанавливать сторонние библиотеки не нужно. Вход в Telegram по номеру,
код подтверждения и пароль от Tronaccs не нужны: используется публичная выдача.
Токен бота можно указать переменной `BOT_TOKEN` вместо редактирования файла.

## Запуск на Bothost

Распакуйте файлы архива в корень проекта. Главный файл: `main.py`.
Укажите токен в `config.json` или переменной `BOT_TOKEN` и запустите проект.
Процесс должен работать постоянно. Сервер слушает `0.0.0.0`, берёт порт из
`PORT`, по умолчанию — `3000`. Для уведомлений домен не требуется.
Для проверки состояния есть `/health`; корневая страница отвечает JSON.
Не запускайте одновременно две копии одного бота.

Если у этого токена уже настроен webhook, программа сообщит об этом и остановится.
Проще создать отдельного бота. Если прежний webhook больше не нужен, его можно
отключить самостоятельно через метод Telegram `deleteWebhook`.
Программа не меняет webhook другого приложения автоматически.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Включить уведомления в личном чате |
| `/stop` | Выключить уведомления и удалить неотправленную очередь этого чата |
| `/status` | Последняя проверка и ошибки сайта или доставки |
| `/check` | Запросить проверку, не нарушая задержку при ошибках сайта |

После первого успешного подключения текущие объявления становятся начальной
точкой: старый каталог не рассылается. Далее приходят вновь появившиеся объявления.
Повышение рейтинга старого объявления само по себе не считается новым размещением.
После `/stop` пропущенные объявления при повторном `/start` не рассылаются.

По умолчанию уведомления доступны всем, кто отправил `/start` боту.
Для личного использования добавьте свой числовой ID в `allowed_chat_ids`, например
`[123456789]`. Ваш ID бот показывает в ответе на `/start`. После изменения файла
перезапустите программу. Список `[]` означает отсутствие ограничения.

## Настройки

| Поле | По умолчанию | Значение |
| --- | --- | --- |
| `bot_token` | заглушка | Токен от BotFather |
| `poll_seconds` | `30` | Пауза между проверками, минимум 15 секунд |
| `max_scan_pages` | `200` | Максимум страниц за проверку для обработки пропусков |
| `allowed_chat_ids` | `[]` | Разрешённые личные чаты; пустой список — все |
| `database` | `state.sqlite3` | Файл истории и очереди рядом с `main.py` |
| `port` | `3000` | HTTP-порт; `0` отключает HTTP-сервер |

При обычной работе новая карточка обнаруживается после следующего опроса.
Точная задержка зависит от сайта, сети, количества новых карточек и очереди отправки.
При сетевой ошибке, HTTP 403, 429 или 5xx бот ждёт и повторяет проверку;
ошибку видно в `/status`. Обход защиты сайта не используется. Если сайт постоянно
отвечает 403, мониторинг с этого сервера недоступен — это нужно решать с площадкой.

## Надёжность и ограничения

- Проверяются все страницы до предыдущей точки проверки; между страницами пауза
  1 секунда. Фильтр сайта `raitingLevelFrom=2` дополняется проверкой поля в коде.
- Новые объявления сохраняются в SQLite вместе с очередью отправки. При ошибке
  доставки они остаются в очереди для повтора.
- Сохранённые ID предотвращают обычные повторы при следующих опросах и перезапусках.
  В редком случае аварии между отправкой в Telegram и записью результата возможен
  повтор: Bot API не предоставляет ключ идемпотентности для `sendMessage`.
- Не удаляйте `state.sqlite3` и файлы `state.sqlite3-wal` / `state.sqlite3-shm`
  во время работы. Для переноса остановите процесс и перенесите базу с программой.
  На хостинге нужен постоянный диск, иначе история пропадёт после перезапуска.
- Если достигнут `max_scan_pages`, частичный результат не считается успешной
  проверкой. Увеличьте значение и перезапустите бота, чтобы обработать большой пропуск.
- Мониторинг опирается на публичную выдачу и даты сайта. Объявление, которое
  появилось и было удалено между опросами, может быть пропущено. Точность рейтинга
  определяется информацией площадки. Изменение API может потребовать обновления кода.
- HTTP-сервер не открывает историю, токен и настройки наружу.

## Проверка без токена

```bash
python main.py --check-source
```

Проверяет текущую первую страницу, структуру данных и сортировку, печатает только
ID, уровень и цену подходящих объявлений. Не отправляет сообщений, не создаёт базу.

Автоматические проверки основной логики (без сети):

```bash
python -m unittest -v
```

## Источники

- Сайт: https://tronaccs.market
- Публичная выдача сайта: https://api.tronaccs.market/items?category=telegram&page=1&orderBy=time_add&orderType=DESC&raitingLevelFrom=2
- Telegram Bot API: https://core.telegram.org/bots/api

22.10.2026 публичная выдача была получена с HTTP 200; фильтр рейтинга вернул
аккаунты с уровнями 2 и 4, включая объявление из запроса пользователя.
При повторной проверке из среды разработки сайт ответил HTTP 403
с текстом `Contact with @tronaccs_support`. Поэтому стабильный доступ с конкретного
хостинга не подтверждён. **Перед запуском выполните `--check-source` на хостинге.**
При постоянном 403 потребуется согласовать доступ с площадкой.
Отправка настоящего Telegram-уведомления требует вашего токена и запуска бота;
без них она не проверялась.
