# Tronaccs Трекер

![Tronaccs Трекер](banner.jpg)

Telegram-бот для уведомлений о новых объявлениях на Tronaccs.
Условия выбираются кнопками прямо в боте и сохраняются отдельно для каждого пользователя.

## Доступ

Доступ к трекеру выдаёт администратор через панель бота. По умолчанию посетитель
доступа не имеет. Он получает сообщение «У вас нету Доступа к Tronaccs Трекеру
напишите Владельцу» и кнопку перехода к [владельцу](https://t.me/klundyy).

Пользователь должен сначала написать боту: после этого он появится в списке
ожидающих. В админ-панели есть списки ожидающих, допущенных и всех пользователей,
кнопки выдачи и отзыва доступа. Имена и usernames берутся из Telegram автоматически:
вручную прописывать идентификаторы в коде или настройках не нужно.

Права администратора и доступы сохраняются в SQLite. Кнопка панели видна только
администраторам. При отзыве доступа мониторинг пользователя останавливается,
неотправленная очередь удаляется, старые кнопки перестают давать доступ.
Настройки фильтров и история остаются в базе.

Каждый `/start` отправляет **новое сообщение** с баннером, даже если старое меню
ещё существует. Это относится и к приветствию допущенного пользователя, и к
сообщению об отсутствии доступа. Обычные переходы по меню редактируют текущий экран.

## Настройки

В меню доступны **28 полей из схемы Telegram-раздела Tronaccs**, полученной 23.10.2026:

- Название объявления, продавец, цена от/до.
- Уровень рейтинга от/до, значение рейтинга, баланс Stars.
- Страны и происхождение аккаунта, включая исключения. Можно выбрать несколько значений.
- Premium и оставшиеся дни, спам-блок, гео спам-блок, пароль 2FA.
- Возраст аккаунта, длина ID, отлёжка, контакты, диалоги, каналы и чаты.
- Админские каналы/чаты и количество подписчиков/участников.
- Обычные и NFT-подарки.

Исходный набор — **уровень рейтинга от 2**. Его можно изменить или снять кнопкой
«Все аккаунты». Проверяется `telegram.raiting_level`, а не репутация продавца.

Баннер используется в главном меню, всех разделах настроек, вводе значений,
поиске, статусе, помощи, подтверждениях и уведомлениях. При переходах бот
редактирует подпись к фотографии.

Все кнопки имеют стандартный красный стиль Telegram (`danger`), включая
ссылки и кнопки в уведомлениях. Дополнительные цветные значки не добавляются.

## Что приходит в уведомлении

Уровень и **количество рейтинга** на аккаунте, точная цена продавца, страна,
Premium, наличие **2FA**, число **обычных подарков** и **NFT-подарков**, ссылка на объявление.
Перед постановкой нового объявления в очередь бот запрашивает его публичную
карточку: общий список не содержит количества подарков. Если карточка недоступна,
неизвестные значения подписываются «Нет данных», а не подменяются нулями.

После основного уведомления с баннером приходят **фотографии подарков с названиями**:

- Обычные подарки с доступным улучшением: название и пометка «можно улучшить до NFT».
- Лимитированные подарки без доступного улучшения: название и пометка
  «улучшение пока недоступно; срок не объявлен». Бот не обещает будущий выпуск улучшения.
- NFT: название, номер и изображение конкретного экземпляра, когда площадка передала его ссылку.

Поддерживаются списки `telegram.gifts` и `telegram.unique_gifts`, включая строки JSON,
старый формат и вложенный формат `[название, номер, slug]`. Повторяющиеся обычные
подарки одного типа объединяются с количеством. Безлимитные подарки без улучшений
из известного каталога не прикладываются. У нераспознанного подарка статус остаётся
неизвестным. Если площадка передала только счётчики, бот явно сообщает, что список
недоступен. Из количества подарков нельзя восстановить их названия или фотографии.
Для старой записи NFT без ссылки на экземпляр изображение коллекции подписывается
как изображение коллекции.

В комплекте — `gift_catalog.json` с названиями и статусами 152 типов подарков.
При наличии подарков каталог обновляется через публичный справочник
[TelegramGiftsAssests](https://github.com/ssamy2/TelegramGiftsAssests), а доступность
улучшения и миниатюры уточняются методом
[`getAvailableGifts`](https://core.telegram.org/bots/api#getavailablegifts) с токеном самого бота.
Копия сохраняется в SQLite; при недоступности справочника используется сохранённая.
Данные справочника могут запаздывать, а неизвестная дата улучшения не прогнозируется.
Фотографии берутся из исходных изображений подарков; WebP конвертируется в JPEG.
Если изображение недоступно, после повторов бот отправляет название и ссылку с
пометкой о недоступности фото. Каждая отправленная часть отмечается в очереди:
обычный повтор после ошибки или перезапуска продолжает доставку с оставшегося подарка.

Цена продавца берётся из ответа сайта без округления до двух знаков и без потери
дробной части через двоичный `float`. Она уточняется по карточке перед уведомлением,
если карточка доступна. Отдельно выводится **цена с публичной комиссией площадки**:
ставка запрашивается у сайта, сумма вычисляется как на странице
`price + ceil(price × commission / 100)`. Например, 575 ₽ при комиссии 15% дают
662 ₽. Это точный расчёт для указанной публичной ставки; персональная комиссия
вошедшего на Tronaccs пользователя может отличаться. Если ставку получить не
удалось, бот показывает только цену продавца, не придумывая итог.
Изменение продавцом цены после проверки не меняет уже отправленное уведомление.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather).
2. Задайте токен переменной **`BOT_TOKEN`** на хостинге. Альтернатива — поле
   `bot_token` в локальном `config.json`; заполненный файл не публикуйте.
3. Нужен **Python 3.10+**. Установите Pillow для обработки фотографий подарков:

   ```bash
   pip install -r requirements.txt
   python main.py
   ```

4. Откройте бота, отправьте `/start`. После выдачи доступа откройте «Настроить фильтры».

**В предыдущей публичной версии `config.json` находился токен. В текущей версии
он удалён. Старый токен нужно перевыпустить через BotFather: удаление из файла
не удаляет его из истории GitHub.**

### Bothost

Главный файл — `main.py`. Загрузите файлы из корня репозитория вместе с
`banner.jpg`, `filter_catalog.json` и `gift_catalog.json`. Установите зависимости из
`requirements.txt`, укажите `BOT_TOKEN`, затем запустите.
Сервер слушает `0.0.0.0`, порт из `PORT` или `3000`; для самого бота домен
не нужен. Требуется постоянный диск для `state.sqlite3`.

Старая база обновляется автоматически. Перед заменой файлов остановите процесс,
сохраните резервную копию базы, затем установите новую версию. Базу удалять не нужно:
подписки и история сохраняются. Одновременно должна работать одна копия бота.
После установки версии с управлением доступом прежние подписчики без выданного
разрешения перестают получать уведомления. Администратор может открыть им доступ
в панели; параметры их фильтров сохраняются.

## Кнопки и ввод

| Раздел | Как пользоваться |
| --- | --- |
| Диапазоны | «Изменить», затем сообщение `100 500`, `100 -` или `- 500` |
| Снять условие | Кнопка «Любое» либо сообщение `-` при вводе |
| Да/нет | Кнопки «Да», «Нет», «Не важно» |
| Страны | Отметьте несколько стран, используйте страницы и поиск по названию/коду |
| Рейтинг | Отдельная кнопка в меню и поиске; «От»/«До» вводятся по одному числу; также доступны диапазон и кнопки 2+, 3+, 5+ |
| Все аккаунты | Снимает все ограничения, включая исходный рейтинг 2+ |
| Сброс | Возвращает рейтинг 2+, остальные условия снимаются |
| Поиск на сайте | Открывает Tronaccs с вашими условиями |

Изменения сохраняются сразу и остаются после перезапуска. Пауза не сбрасывает
настройки. При активации нового набора условий текущие объявления становятся
начальной точкой: бот не рассылает старый каталог. Настройки пользователя не
меняют условия других пользователей. Одинаковые наборы объединяются в одну проверку.

| Команда | Действие |
| --- | --- |
| `/start` | Новое сообщение; включить мониторинг и открыть меню при наличии доступа |
| `/settings`, `/filters` | Открыть фильтры |
| `/rating` | Изменить нижнюю и верхнюю границы уровня рейтинга |
| `/stop` | Остановить уведомления |
| `/status` | Последняя проверка и ошибки |
| `/check` | Проверить, в том числе при паузе; уведомления при паузе не включаются |
| `/menu`, `/cancel` | Главное меню / отмена ввода |
| `/help` | Помощь |

## Конфигурация

| Поле | Значение по умолчанию |
| --- | --- |
| `bot_token` | Пусто; используйте `BOT_TOKEN` или локальный файл |
| `poll_seconds` | 30; минимум 15 секунд |
| `max_scan_pages` | 200 страниц за проверку одного набора условий |
| `database` | `state.sqlite3` |
| `port` | 3000; `0` отключает HTTP; `PORT` имеет приоритет |

Токен — единственное обязательное значение. Номер телефона, код входа в Telegram
и пароль от Tronaccs для публичной выдачи не нужны. При наличии старого webhook
программа останавливается с объяснением: используйте отдельного бота или заранее
отключите ненужный webhook.
Старое поле `allowed_chat_ids` больше не используется: доступами управляет панель.

## Проверки

```bash
python -m unittest -v
python main.py --check-source
```

Первая команда проверяет логику и меню без сети. Вторая проверяет доступ к
публичной выдаче без токена и отправки сообщений. `/health` отвечает состоянием
процесса и активных проверок, не раскрывая настройки и токены.

23.10.2026 проверены живая схема фильтров, справочники и выдача с условиями:
рейтинг 2+, цена до 1000 ₽, Premium отсутствует; также запрос с рейтингом от 0
до 1. Сайт ответил успешно. Telegram-экраны, загрузка баннера, кнопки и доставка
проверены имитацией Bot API; реальная отправка с пользовательским токеном не выполнялась.

24.10.2026 пройдены 95 автоматических проверок, включая названия и статусы подарков,
преобразование исходного WebP в JPEG, отправку фотографий, продолжение очереди после
ошибки и перезапуска, остановку/отзыв доступа между частями уведомления.
Проверен настоящий WebP из каталога. Во время этой проверки Tronaccs ответил HTTP 403;
формат списков проверен по коду публичной карточки сайта и тестовым ответам.

## Особенности работы

При HTTP 403/429 или сетевой ошибке бот показывает проблему в статусе и делает
паузу перед повтором. Сайт может ограничить доступ с конкретного хостинга.
Опрос может пропустить карточку, удалённую между проверками. Скорость зависит
от сайта, числа разных наборов, страниц и очереди доставки.

История и очередь хранятся в SQLite. Обычные повторы при опросах и перезапусках
отсекаются. При аварии между отправкой сообщения и сохранением результата возможен
редкий повтор. После смены фильтра неотправленная очередь старого набора этого
пользователя удаляется. Изменение параметров старой карточки не считается новым
размещением. Не удаляйте файлы базы во время работы. Для переноса остановите процесс.

Фильтры передаются с параметрами из схемы сайта. Поля, доступные в выдаче
(включая рейтинг, цену, страну и Premium), дополнительно проверяются локально.
Для остальных условий источником результата служит фильтрация площадки.
Справочники и схема в `filter_catalog.json` соответствуют проверке 23.10.2026;
изменения API могут потребовать обновления файла или кода.
